# Estimating Cognitive Load & Engagement from Learning Data (OULAD)

A log-based pipeline that estimates a cognitive-load proxy and engagement from learning-platform data in the
[Open University Learning Analytics Dataset (OULAD)](https://analyse.kmi.open.ac.uk/open_dataset), using random
forests, LSTM sequence models and SHAP explanations. The pipeline was then stress-tested against its own
methodological weaknesses: a feature-leakage audit and multi-seed significance tests.

- **Preprint:** Zafar, S. (2026). *Toward Estimating Cognitive Load and Engagement in Digital Learning Environments
  Using Behavioral Learning Analytics.* OSF Preprints. https://doi.org/10.35542/osf.io/bgnkw_v1
- **Project page:** https://sabazafar209-wq.github.io/sabazafar.github.io/OULAD_Project.html

## Key results

| Evaluation | LSTM macro F1 | High-load F1 |
|---|---|---|
| First reported (v1, single split) | 0.650 | 0.24 |
| Entangled labels and inputs (v2, 5 seeds) | 0.536 ± 0.022 | 0.390 ± 0.023 |
| **Strict feature-disjoint (5 seeds)** | **0.483 ± 0.004** | **0.244 ± 0.010** |

- Part of the first result came from feature-family leakage between labels and model inputs. The strict
  feature-disjoint test is the headline result (Mann-Whitney U, one-tailed p = 0.004).
  **[How I audited this, step by step →](docs/leakage-audit.md)**
- In SHAP explanations, irregular and long gaps between study sessions (`idle_gap_std`, `idle_gap_max`) are the
  strongest drivers of a "high load" prediction.
- Across 5 seeds, sequence oversampling did **not** improve on a class-weighted baseline (Wilcoxon p = 0.625), so an
  earlier single-split claim was retracted. Focal loss underperformed in 5 of 5 seeds (p = 0.0625, the minimum at n = 5).
- High-load precision never exceeds 0.29, so roughly 3 in 4 "high load" flags are false alarms.
- The random forest's 0.98 macro F1 predicts labels clustered from its own features. It checks cluster
  consistency and is not a measure of predictive validity.
- Labels come from K-means clusters of struggle-related behavior (silhouette 0.242 / 0.175). They are best read as
  an assessment-defined struggle proxy, not a validated measure of cognitive load.

## Repository structure

```
scripts/   analysis pipeline (run from the repository root)
data/      derived feature and label tables (raw OULAD files go in data/raw/)
models/    result metrics as JSON (multi-seed results, effect sizes, statistical summary)
figures/   confusion matrices, SHAP plots, training curves, multi-seed box plots
docs/      leakage-audit write-up
```

## Pipeline

| Step | Script | What it does |
|---|---|---|
| v1 | `01_baseline_models.py` | Random forest baselines for cognitive load and engagement |
| v1 | `02_lstm_model.py` | LSTM on per-assessment event sequences |
| v1 | `03_explainability.py` | SHAP analysis of the random forest cognitive-load model |
| v2 | `06a_cache_weekly.py` | Aggregates the 10.66M-row clickstream into weekly clicks |
| v2 | `04_clickstream_features.py` | Idle-gap, burstiness, cramming and activity features |
| v2 | `05_merge_and_relabel.py` | Merges features and re-derives labels |
| v2 | `06_lstm_weekly_clickstream.py` | LSTM on weekly click sequences |
| v3 | `07a_prep_cache.py`, `07b_train_regime.py`, `07_imbalance_comparison.py` | Class-imbalance regimes (weighted, focal, oversampling) |
| v4 | `08a_*.py` | Builds clickstream-only sequences and feature-disjoint labels |
| v4 | `08b_*.py`, `08c_*.py`, `08d_*.py` | Strict-disjoint test and multi-seed runs |

## Reproducing

```bash
pip install -r requirements.txt
python scripts/01_baseline_models.py      # runs on the included data/oulad_labeled.csv
```

Scripts that start from raw data need the OULAD tables (`studentInfo.csv`, `studentAssessment.csv`,
`studentRegistration.csv`, `assessments.csv`, `courses.csv`, `vle.csv`, `studentVle.csv`) downloaded from the
[OULAD website](https://analyse.kmi.open.ac.uk/open_dataset) into `data/raw/`. The large intermediate files
(`oulad_weekly_clicks.csv`, the cached sequence pickle and `oulad_sequences_raw.csv`) are not included because of
their size. They are regenerated by the v2 and v4 preparation scripts.
